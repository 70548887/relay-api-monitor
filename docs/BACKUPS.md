# 数据备份与恢复

v1.5.0 新增后台 `/admin/backups`，仅管理员可访问。数据库由 Schema 3 前向迁移到 Schema 4；不要把只支持 Schema 3 的旧程序直接指向迁移后的数据库。

## 首次配置

1. 登录后台，打开“备份与恢复 → 存储与恢复密钥”。
2. 生成恢复密钥，立即下载并独立保管 `AGE-SECRET-KEY-...` 私钥。服务端不持久保存私钥。
3. 保存以 `age1...` 开头的恢复公钥，并按页面提示输入对应私钥完成校验。
4. 默认选择本地保存；需要异机副本时配置 S3 兼容存储并测试连接。
5. 点击“立即备份”，等待本地保存及远端校验完成。定时备份默认关闭，另行启用。

丢失恢复私钥将失去加密包的解密能力。原站点的数据库、`master.key` 或管理员密码不能代替恢复私钥。更换恢复公钥只影响之后的备份；旧私钥仍应保留。

## 备份内容与文件

整站快照包含管理员、普通用户、密码哈希、平台分组、后台及用户连接凭据、模型、任务、监控、作品、私有测试记录和系统设置。

新包格式为 `.zip.age`，整包公钥加密，内部包含：

```text
relaylab.db
master.key
manifest.json
```

manifest 分别记录包格式版本、数据库版本、程序版本、文件大小及 SHA-256。上传 S3 后会重新下载密文并计算哈希，回读校验通过才显示远端成功。

外部 `config.yaml`、环境变量、程序、日志、GitHub Token、代理配置和恢复私钥不自动加入备份。迁移到新服务器时独立准备部署配置及 S3 凭据。

备份使用 SQLite 一致性快照，不直接复制运行中的数据库/WAL。本地默认保存到数据目录同级 `backups/instances/<实例标识>/`，Docker 为 `/var/lib/relaylab/backups/instances/<实例标识>/`。实例标识根据规范化数据目录路径生成，同一父目录的不同实例不会共用恢复日志、操作锁或备份索引。明文暂存目录受限并在操作后清理，不使用容器的 64 MiB `/tmp`。

此前本地候选使用的共享 `backups/` 文件不会自动删除或混入新实例目录；需要使用“导入并预检”选择对应文件。旧候选无归属恢复日志会被拒绝，不会猜测其所属实例。

## S3 与 R2

配置 Endpoint、Region、Bucket、Prefix、Access Key ID、Secret Access Key 和路径风格。R2 Region 使用 `auto`；Endpoint 使用账户的 S3 兼容地址。普通 S3 填实际区域。

Secret 留空保留原值，填写则替换；读取接口不返回凭据。变更连接身份或 Endpoint 时按页面要求重新填写凭据。旧备份仍引用原存储修订，变更当前配置不会移动已有文件。

“测试连接”执行随机小对象的写、读、哈希比较和删除。失败信息显示具体阶段；删除失败时可能保留测试对象。上传失败保留本地加密文件，“重试上传”不会重新生成数据库快照。

页面展示当前存储修订最近一次测试或传输的时间与结果；“已配置”不代表连接已通过验证。重试会先回读已存在的对象，匹配时复用，内容不匹配时拒绝覆盖。

默认仅允许 HTTPS 公共存储地址。自建内网 MinIO 需要在服务进程环境变量 `RELAYLAB_BACKUP_ALLOWED_STORAGE_HOSTS` 中明确列出允许的主机，多个主机用逗号分隔；不要使用全局关闭地址校验的方式。Docker 需要将该变量加入服务的 `environment` 并重新创建容器，仅写入 `.env` 而未传入容器不会生效。

```dotenv
RELAYLAB_BACKUP_ALLOWED_STORAGE_HOSTS=minio.internal.example
```

## 定时、归档与清理

默认策略：

- 定时关闭；启用后使用 `0 2 * * *`，时区 `Asia/Shanghai`，即北京时间每天 02:00。
- 普通备份保留 14 天、最多 10 份，达到任一清理条件时淘汰旧普通备份。
- 对应条件填写 0 表示禁用该条件；两项均为 0 时不按普通策略自动清理。
- 月度归档默认关闭；启用后可选日期及永久或有限份数保留。
- 保存策略不自动执行一次备份；立即执行使用单独按钮。

月度归档只认领成功定时备份。当日失败可顺延到同月下一次成功备份；不存在的日期折算月末。一个文件可以覆盖同月多个已到期归档日期，不重复存储。归档独立于普通份数，永久保护不会因关闭规则自动取消。

正在恢复、等待上传重试、受保护或最后一个成功恢复点不会按普通规则误删。删除失败保留索引供重试。服务停机期间不逐次补跑所有遗漏周期。

备份记录支持按状态、手动/定时、普通/月度/手动保护和北京时间日期范围筛选，筛选在服务端对完整记录集合执行。保存更改后的保留策略前，页面先显示清理候选数量、大小及文件列表，再由管理员确认。

## Windows 与 Linux 原生恢复

### 后台在线恢复

需要带 `restore_v1` 能力的新 launcher。协议仍为 2；旧 launcher 可以继续管理网站和备份，但不支持本页在线恢复，需要手动更新完整部署包中的 launcher。

管理员再次验证密码后选择记录或上传包，提供恢复私钥并执行预检。预检先校验加密、成员、哈希、数据库版本、完整性和全部保存凭据，不改当前数据。

确认执行后系统排空请求，停止 Worker 和网站，保存当前数据安全快照，再事务性替换数据库与主密钥。失败时恢复操作前数据。页面转入独立只读恢复进度页 `/restore-progress/<操作ID>`，重启期间使用短期只读操作凭证查询结果，旧管理员会话失效后仍可显示进度，不因此获得后台写权限。凭证只保留在当前标签页内存，刷新或重新打开页面后需要重新登录查询。

恢复后旧登录会话失效，请使用快照中的账号重新登录。快照中的旧排队任务终止，已发送但结果不明的任务标记未知，不重复调用模型。备份自动计划和清理先暂停，完成索引核对后再启用。

在新目录或新数据卷恢复时，快照里登记的旧本地文件可能不在新环境。“核对备份索引”会继续暂停计划，不会把这些文件当作已经删除。确认它们确实遗失后，可对相应记录执行“确认副本遗失”，再次核对后解除阻塞。该操作只确认本地副本不可用，不删除云端对象；有远端副本的记录仍须完成远端验证，不能用此操作绕过。

### 命令行恢复到新目录

只验证备份而不恢复时，可独立执行：

```sh
./bin/relaylab verify-backup --input /secure/relaylab.zip.age --identity-file /secure/recovery.key
```

该命令不读取应用配置，也不打开当前数据目录。仅在受限缓存目录校验解密、包成员、数据库和凭据后输出 `valid` 与 manifest JSON；可用 `--staging-dir /secure/verify-staging` 指定具有足够空间的暂存位置。正常结束时，无论校验成功或失败都会清理本次明文副本。旧版未加密 ZIP 可省略私钥参数。

预检缓存使用独占锁，避免并行预检清理正在使用的目录。异常退出后，下一次预检会回收超过 2 小时、具有匹配归属标记的旧明文目录；锁文件本身不包含密钥。CLI 不是常驻清理服务，未再次运行时不会定时回收；此前无归属标记的旧候选目录须由管理员核对后处理。

Windows：

```powershell
.\scripts\backup.ps1 -Recipient 'age1替换为恢复公钥' -OutputPath 'D:\backups\relaylab.zip.age'
.\scripts\restore.ps1 -InputPath 'D:\backups\relaylab.zip.age' -DataDir 'D:\relaylab-restored\data' -IdentityFile 'D:\private\recovery.key'
```

Linux：

```sh
./bin/relaylab backup --data-dir ./data --output ./backups/relaylab.zip.age --recipient 'age1替换为恢复公钥'
./bin/relaylab restore --data-dir ./restored/data --input ./backups/relaylab.zip.age --identity-file /secure/recovery.key
```

私钥通过受限文件输入，不把私钥正文放进命令行。目标目录必须为空；已有数据不会被覆盖。CLI 也会清理旧会话、终止旧队列并暂停备份清理。

省略 `--recipient` 的 CLI 备份继续输出兼容旧 launcher 的未加密 ZIP。它包含主密钥，应作为本机受限安全快照管理；云端日常备份使用后台加密包。旧 ZIP 恢复不需要 `--identity-file`。

## 宝塔 Docker 恢复

后台提供恢复预检，首版实际恢复使用新命名卷。脚本只操作新卷，不覆盖原卷、不自动修改 `.env`、不删除任何旧卷。

在包含 `compose.yaml` 的发布包或源码项目中，先准备本机备份包及恢复私钥文件，然后执行：

```sh
sh scripts/restore-docker.sh /secure/relaylab.zip.age relaylab-restored-20261029 /secure/recovery.key
```

脚本确认卷名尚未使用，先在新卷中完成解密、恢复与数据校验，并设置 UID/GID 10001 所有权。验证失败时不停止当前服务；验证成功后才停止旧服务并提示显式切换卷。一次性恢复容器以 root 执行，仅挂载新卷和只读输入文件，关闭网络，不挂载 Docker socket。旧版明文 ZIP 可省略最后的私钥文件参数。

成功后按脚本提示在项目私有 `.env` 中设置：

```dotenv
RELAYLAB_DATA_VOLUME=relaylab-restored-20261029
```

再执行：

```sh
docker compose up -d --no-build --force-recreate
docker compose ps
docker compose logs --tail 100 relaylab
```

确认容器 healthy、账号可登录、平台及用户 Key 可解密、历史完整后再恢复正常计划，并保留原卷。恢复校验失败会保留新卷便于检查，原服务和原卷均不变；验证成功且旧服务已停止后，如决定不切换，可用原来的 `.env` 执行 `docker compose up -d --no-build` 启动原部署。

不要先初始化新卷管理员；不要使用 `docker compose down -v` 删除卷。未通过恢复校验的新卷不要切换上线。

## 云端备份目录与迁移复核

在“备份记录 → 云端备份目录”中，按已保存 S3 配置的 Bucket/前缀扫描 `.zip.age` 对象。列表分页读取，未识别对象显示“待核对”；扫描只获取目录，不代表备份可恢复。选择对象后输入对应恢复私钥并再次验证管理员密码，服务端下载并校验加密、包成员、SQLite、主密钥与关联凭据后，创建受保护的导入记录。

导入只增加备份文件和记录，不恢复业务数据库，也不执行旧任务。重复导入同一候选复用原记录；私钥不持久保存。云端导入记录解除保护并删除后，只删除本机副本和记录，保留云端源对象。旧版明文 ZIP 使用普通“导入并预检”入口。

云端目录扫描需要配置前缀的列表权限，导入需要对象读取权限；权限不足会明确失败。源对象的 ETag 在下载时用于固定版本，但最终可恢复性仍以实际加密和数据库校验为准。提供商兼容性需使用实际 R2/S3 账户另行验收。

迁移到新数据目录时，可以将已有加密包及其 catalog、storage 目录一起复制到新实例的备份目录。复核会以已登记文件名、SHA-256 和大小确认文件后重新绑定路径，不接受路径逃逸、链接或篡改文件。目录记录具有主密钥归属证明；未被当前数据集引用的旧配置、异主密钥或无归属目录会保留并提示待核对，不自动删除，也不作为新活动配置。

保存新存储配置使用数据库原子分配修订号；恢复旧数据库后导入的历史修订不会覆盖已选择的活动配置。当前数据集实际引用的副本或凭据无法验证时，仍保持清理冻结。

上传备份包使用独立 30 分钟读取期限，其他请求保留默认短期限。超时、超出 3 GiB 和磁盘写入失败分别报告。

## 验证边界

本版备份功能需以隔离目录/新卷恢复结果验收，不能用“文件已生成”或“上传返回成功”代替恢复验证。

Go 归档、凭据、操作锁及 launcher 故障测试使用真实 SQLite 和本地测试夹具。真实 R2、宝塔实机 Docker、连续 24 小时稳定性是否执行，以本版最终测试记录为准；没有对应记录时均为未执行，不代表所有 S3 兼容平台已验证。
