# Release v1.6.0 - 分组任务与测试参数改进

## 发布信息

- 类型：正式功能版本；Tag `v1.6.0`，版本来源为根目录 `VERSION`。
- 支持 Windows amd64、Linux amd64 和 Linux arm64。
- 数据库保持 Schema 4，launcher 协议 2、`usage_guard: 1` 和 `restore_v1` 能力要求不变。
- 发布时间以 GitHub Release 为准；以下操作时间统一为北京时间。

## 功能与修复

- “平台与分组”新增直达该分组“任务与作品”的入口；任务与作品页可按分组筛选任务和留存作品。分组任务查询独立取最近 100 条，繁忙分组不会挤掉其他分组的记录；作品每页 25 条，可继续翻页浏览全部留存作品。
- 平台、分组的“排序”数值相同时按创建时间排列；创建时间相同再按 ID 排列，避免名称变化打乱已添加的顺序。
- 同一模型已有同类活动任务时，手动提交返回 `model_busy`，指出占用的任务及状态；执行测试窗口提供查看该分组任务的入口。
- 作品因输出 Token 上限截断时，任务错误写明本次上限和调整位置。分组“执行测试”窗口可修改所选模型的“创作最大 Tokens”，保存后定时创作也使用新值。
- 模型上下文窗口耗尽时显示独立错误提示，建议缩短输入或更换模型，避免误认为调大输出额度即可解决。
- Go 构建工具链升级至 1.26.11，以修复依赖扫描命中的标准库漏洞。
- 新增到 Anthropic Messages 协议分组的模型，作品输出上限默认 32,000 Tokens，供默认启用思考的模型留出额度；其他协议默认仍为 8,192。已有模型不改动，管理员可自行调整。普通用户在线创作测试的默认上限随所选协议变化，纯文本测试仍为 1,024。

## 安装与升级

1. 升级前保存数据库与 `master.key` 的受限安全快照，并保管离线恢复私钥。
2. v1.5.1 原生部署可通过后台在线升级或替换完整安装包升级；已有协议 2 且具备 `restore_v1` 的 launcher 可继续使用。
3. 更早版本首次升级至 Schema 4 时遵循 [升级说明](https://github.com/70548887/relay-api-monitor/blob/v1.6.0/docs/UPDATES.md)。只支持 Schema 3 的旧程序不能直接打开已迁移数据库。
4. 宝塔／Docker 部署重新构建镜像并重建容器，保留持久化数据卷；容器内不执行二进制自替换。
5. 32,000 Tokens 是新增 Anthropic 模型的默认上限，不保证上游支持该值或完整输出；可根据模型限制、费用和任务需要在后台调整。

配置与恢复步骤见 [备份与恢复说明](https://github.com/70548887/relay-api-monitor/blob/v1.6.0/docs/BACKUPS.md)，宝塔部署见 [Docker 文档](https://github.com/70548887/relay-api-monitor/blob/v1.6.0/docs/DOCKER.md)。

## 附件与校验

固定 11 个附件：6 个主程序／launcher 裸程序、3 个完整部署包、`manifest.json` 和 `SHA256SUMS`。

- Windows：`relaylab-windows-amd64-1.6.0.zip`
- Linux x86_64：`relaylab-linux-amd64-1.6.0.tar.gz`
- Linux ARM64：`relaylab-linux-arm64-1.6.0.tar.gz`

Manifest 包含完整源码 Commit、统一 UTC 构建时间、系统／架构、Schema 4、兼容范围、大小和 SHA-256。发布流水线先上传草稿，再重新下载并核对全部附件，验证通过后发布并设为最新版。部署包不包含数据库、`master.key`、本机配置、Token、日志或真实存储凭据。

Linux/macOS 使用 `sha256sum -c SHA256SUMS`；Windows 使用 `Get-FileHash` 与校验清单对照。

## 验证与已知限制

- 发布门禁运行 Go 全量测试、`go vet`、前端单元测试与类型检查、打包回归、依赖检查和 Linux race 检查；Windows／Linux amd64 还执行真实程序备份恢复与升级回滚。Docker amd64／arm64 验证非 root 启动、双进程就绪、持久化与新卷恢复。ARM64 容器使用 QEMU，不等于原生 ARM64 实机验收。
- 本地启动使用独立的空白数据目录，健康检查、首页与公开监控接口返回 200，公开状态确认 Worker 租约在线。实际模型调用需要部署者自己的分组与密钥。
- 真实 R2 大型加密备份上传、下载恢复、宝塔实机部署、Docker 大于 64 MiB 的加密恢复完整链路和连续 24 小时稳定性仍需单独验收。
- 发布不会自动替换现有本机程序；安装与配置变更以部署操作为准。
