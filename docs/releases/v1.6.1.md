# Release v1.6.1 - 修复 Linux 在线升级暂存文件权限

## 发布信息

- 类型：正式修复版本；Tag `v1.6.1`，版本来源为根目录 `VERSION`。发布状态和时间以 GitHub Release 为准。
- 支持 Windows amd64、Linux amd64 和 Linux arm64。
- 数据库保持 Schema 4，launcher 协议 2、`usage_guard: 1`、`restore_v1` 能力要求不变。已发布的 v1.6.0 Tag 与 Release 不覆盖、不替换。

## 修复

- Linux 原生在线升级的下载器使用 `os.CreateTemp` 创建暂存文件，默认权限为 `0600`。旧版下载完成并通过大小、SHA-256 校验后直接重命名；启动器接着执行暂存文件的 `version --json`，因缺少执行权限而报 `permission denied`。SHA-256 只验证字节，不验证文件模式。
- 下载器现在仅对已经完整下载且校验大小、SHA-256 成功的临时文件设置 `0700`，检查权限设置结果，并在持久化及提交为可安装状态之前完成。失败或不完整的下载不会成为可安装文件。
- 对已有缓存，程序先核对暂存路径、普通文件属性、大小及 SHA-256，再通过已打开的文件句柄修复所有者可执行权限。校验失败时不提升权限，继续按现有流程拒绝该缓存。

## 安装与旧版恢复

1. 升级前保存数据库与 `master.key` 的受限安全快照，并保管离线恢复私钥。原生部署先确认现有 launcher 协议、程序架构及目标 Release 的 Manifest 与当前数据库 Schema 兼容；Docker／宝塔容器部署按容器升级流程重建镜像和容器，保留数据卷。
2. 正在运行 v1.5.1 或 v1.6.0 的 Linux 实例无法在安装本版之前自动得到修复。如果后台已下载完成但安装时报 `version probe: permission denied`，在最终下载之后按 [旧版恢复步骤](https://github.com/70548887/relay-api-monitor/blob/v1.6.1/docs/UPDATES.md#旧版-linux-暂存文件权限失败的恢复)核对并只修复该次升级的确切暂存文件；随后在后台重新检查更新，使缓存恢复为 `ready`，再安装。设置权限后不要重新下载，否则旧版会再次创建 `0600` 文件。
3. 若暂存文件 SHA 与可信 Manifest 不符、实际路径不是私有 `data/updates/<operation-id>/` 内的普通文件，停止本次安装并重新获取可信附件。若文件已是 `0700` 仍不能执行，检查所在挂载点 `noexec`、目录访问权限或系统安全策略；`chmod` 不会解除 `noexec`。不要对目录递归设置权限，也不要使用 `777`。
4. 旧版实例也可通过受控维护流程部署完整 v1.6.1 安装包。v1.5.1、v1.6.0 均不能靠重新下载来自动修复此次暂存权限问题。升级成功后核对网站与 Worker 的实际版本和健康状态。

## 附件与校验

稳定 Release 固定包含 **11 个附件**：Windows amd64、Linux amd64、Linux arm64 各 1 个服务端和 1 个 launcher 裸可执行文件，共 6 个；Windows 完整 ZIP、两个 Linux 完整 tar.gz，共 3 个；`manifest.json` 和 `SHA256SUMS`。

- Windows 完整包：`relaylab-windows-amd64-1.6.1.zip`
- Linux amd64 完整包：`relaylab-linux-amd64-1.6.1.tar.gz`
- Linux arm64 完整包：`relaylab-linux-arm64-1.6.1.tar.gz`

Manifest 包含完整源码 Commit、统一 UTC 构建时间、系统／架构、Schema 4、兼容范围、大小和 SHA-256。正式附件由与 Tag 对应的已提交源码构建；发布流水线须通过门禁，先上传草稿并重新下载核对所有附件，再发布为正式版。完整包不包含数据库、`master.key`、本机配置、Token、日志或真实存储凭据。Linux 使用 `sha256sum -c SHA256SUMS`；Windows 使用 `Get-FileHash` 与清单对照。

## 验证与已知限制

- 发布门禁要求 Go 全量测试、`go vet`、前端测试及类型检查、打包回归、依赖检查与 Linux race 检查；Windows／Linux amd64 还须执行真实二进制备份恢复、升级回退与容器检查。实际通过情况以本次 CI 与发布记录为准，不能用过去版本的结果替代。
- Linux 回归应由真实下载路径产生暂存文件，验证执行权限、直接运行 `version --json`、旧 `0600` 缓存的哈希核对与修复，以及哈希错误时不修复。只通过 SHA-256 或使用预先设为 `0700` 的夹具不能覆盖此问题。
- ARM64 容器运行检查若使用 QEMU，不等于原生 ARM64 主机验收。真实线上实例、宝塔实机、连续 24 小时稳定性与大型加密备份恢复需要单独验收；此说明不代表已在用户服务器完成修复。
