# Release v1.2.2 - 修复在线升级与完整部署包

## 修复

- Windows PowerShell 脚本使用 UTF-8 BOM，修复英文版 Windows PowerShell 5 将中文按 ANSI 解码后出现语法错误的问题。

- 升级操作由后台任务继续执行，页面断线后持续重连并保留最终错误；下载只有校验成功才进入 ready，安装由协议 2 启动器接管。
- 新程序启动后核对实际版本、commit、数据库和 Worker；失败恢复旧程序及升级前数据，页面不再把连接恢复或请求受理当成升级成功。
- 启动停止脚本遵循 YAML、环境变量与显式参数优先级，支持含空格路径；启动器使用系统分配的回环控制端口，停止前核对进程路径和启动时间。
- 首次空数据目录启动时，等待网站完成数据库初始化并报告就绪后再启动 Worker，避免首次运行抢先访问不存在的数据库。
- 发布版本统一读取 VERSION，网站和启动器使用同一 commit/构建时间；补齐三平台完整安装包、协议和数据库兼容信息，修正 SHA256SUMS 的目录前缀。
- Release 先上传草稿并重新下载校验，再设为正式最新版；已发布版本不可覆写。

## 安装

- Windows amd64 下载 `relaylab-windows-amd64-1.2.2.zip`，解压后运行 `scripts/start.ps1`；首次访问默认地址 `http://127.0.0.1:42783` 创建管理员。
- Linux amd64 / arm64 下载对应 `relaylab-linux-架构-1.2.2.tar.gz`，保留完整目录结构，参考 `deploy/README.md` 使用 systemd，或运行 `sh scripts/start.sh` 前台启动。
- 裸可执行附件用于已有安装的更新；首次安装使用完整压缩包。下载 `SHA256SUMS` 后在附件目录执行 `sha256sum -c SHA256SUMS`（Linux）。

## 迁移

- **v1.2.0 / v1.2.1 必须先手动迁移一次完整包。** 旧启动器升级交接不可靠；本次同时替换服务端、启动器及 scripts，后续才使用协议 2 在线升级。
- 先运行旧版停止脚本并确认网站和 Worker 均已退出，再完整备份数据库与 master.key。解压新包到新目录，将原 data 和本地 config.yaml 一起迁入，或用环境变量继续指向原数据目录。
- 不要用 config.example.yaml 覆盖已有 config.yaml，不要用空数据目录替换现有数据库和密钥；数据库 schema 仍为 1，无需手工修改表。
- `auto_restart: false` 只准备升级包，显示“等待手动重启”；未完成新版本健康验证前不会宣称成功。

## 验证

- 发布流水线包含 Go 测试与 vet、前端测试与类型检查、打包隔离与校验测试，以及 Windows / Linux amd64 的真实二进制升级和恢复测试。
- Manifest、SHA256SUMS 与草稿下载校验覆盖全部 6 个可执行文件、3 个完整压缩包及 Manifest。
- 升级后在后台核对当前版本 1.2.2、目标 commit、Worker 在线、原平台/任务/历史仍存在；失败时查看操作错误和数据目录日志。

## 已知限制

- Linux arm64 已纳入交叉编译与附件校验，未在 arm64 主机执行真实启动/升级测试。
- GitHub Release 附件通过 HTTPS 与 SHA-256 校验，当前没有独立签名信任链；下载仍依赖 GitHub 或管理员配置的代理可达。
- 更新不迁移外部服务配置或 systemd 用户权限；自定义数据目录需同步调整服务的 ReadWritePaths。
