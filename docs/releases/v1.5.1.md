# Release v1.5.1 - 修复 S3/R2 连接与配置验证状态

## 发布信息

- 类型：正式修复版本；Tag `v1.5.1`，版本来源为根目录 `VERSION`。
- 支持 Windows amd64、Linux amd64 和 Linux arm64。
- 数据库保持 Schema 4，launcher 协议 2、`usage_guard: 1` 和 `restore_v1` 能力要求不变。
- 发布时间以 GitHub Release 为准；以下操作时间统一为北京时间。

## 修复

- S3/R2 连接共享 `upstream.dns_over_https` 配置与解析缓存。系统 DNS 全部返回代理 Fake-IP 时，使用已配置的安全解析器；解析结果仍经过公网校验并固定 IP 拨号。
- 测试按钮旁持续显示等待时间和最终结果，区分 DNS、连接、TLS、超时、取消、身份验证、操作权限及读写清理阶段。失败后刷新存储健康状态，结果不再只出现在页顶。
- 连接测试成功和失败均提供诊断编号并写入脱敏运行日志及管理审计；上游 401/403 不会撤销本地管理员会话。
- 写入可能已完成但响应失败时，仍尝试清理本次随机测试对象。条件写入禁用该次 PUT 的自动重试，同名冲突不覆盖或删除已有对象；主错误和清理失败分别保留。
- 完全相同的规范化配置及凭据重复保存，保留当前 ID、修订、创建时间及健康状态；配置或凭据真正改变才生成未验证的新修订。
- 测试结果由服务端绑定实际使用的修订。草稿、旧修订或已修改表单的结果明确标为历史／待核对，不冒充当前配置验证成功；并发保存不会把迟到结果写到新修订。
- 修复保存相同配置后字段被清空；同端点可保留空白的已有凭据。数据库已提交而外部恢复目录未写入时，同配置重试会补齐目录，损坏或身份不符的文件会明确报错。
- 修正三处依赖锁文件的版本标注，使其与已有完整性固定的下载包一致；实际依赖版本与下载摘要未改变。

## 安装与升级

1. 升级前保存数据库与 `master.key` 的受限安全快照，并保管离线恢复私钥。
2. v1.5.0 原生部署可通过后台在线升级或替换完整安装包升级；不需要重启电脑。已有协议 2 且具备 `restore_v1` 的 launcher 可继续使用。
3. 更早版本首次升级至 Schema 4 时遵循 [升级说明](https://github.com/70548887/relay-api-monitor/blob/v1.5.1/docs/UPDATES.md)。只支持 Schema 3 的旧程序不能直接打开已迁移数据库。
4. 宝塔／Docker 部署通过重新构建镜像并重建容器升级，保留持久化数据卷；容器内不执行二进制自替换。
5. Fake-IP 环境可设置 `upstream.dns_over_https` 或 `RELAYLAB_UPSTREAM_DNS_OVER_HTTPS` 后重启程序。S3 不自动使用系统代理或仅面向 GitHub 的 `update.proxy`，不要全局关闭地址校验。
6. 历史未验证修订不会被自动标成成功。对当前配置测试通过后，相同配置再次保存会保留验证结果。

配置与恢复步骤见 [备份与恢复说明](https://github.com/70548887/relay-api-monitor/blob/v1.5.1/docs/BACKUPS.md)，宝塔部署见 [Docker 文档](https://github.com/70548887/relay-api-monitor/blob/v1.5.1/docs/DOCKER.md)。

## 附件与校验

固定 11 个附件：6 个主程序／launcher 裸程序、3 个完整部署包、`manifest.json` 和 `SHA256SUMS`。

- Windows：`relaylab-windows-amd64-1.5.1.zip`
- Linux x86_64：`relaylab-linux-amd64-1.5.1.tar.gz`
- Linux ARM64：`relaylab-linux-arm64-1.5.1.tar.gz`

Manifest 包含完整源码 Commit、统一 UTC 构建时间、系统／架构、Schema 4、兼容范围、大小和 SHA-256。流水线先上传草稿，再重新下载核对全部附件，验证通过后发布并设为最新版。部署包不包含数据库、`master.key`、本机配置、Token、日志或真实存储凭据。

Linux/macOS 使用 `sha256sum -c SHA256SUMS`；Windows 使用 `Get-FileHash` 与校验清单对照。

## 验证与已知限制

- 发布门禁包含 Go 全量测试、`go vet`、前端测试与类型检查、打包回归、依赖检查，以及新增备份模块的 Linux race 检查。
- Windows／Linux amd64 执行真实程序备份恢复和升级回滚；Docker amd64／arm64 执行非 root 启动、双进程就绪、持久化和新卷恢复。ARM64 容器使用 QEMU，不等于原生 ARM64 实机验收。
- 本地定向回归覆盖安全 DNS、凭据脱敏、失败清理、幂等保存、并发修订、恢复目录重试、草稿与旧结果关联，并完成桌面／手机浏览器夹具验证。
- 2026-10-30 22:35:47，用户本机配置的 R2 连接测试实际完成写入、读取校验与删除，耗时约 2.9 秒。该结果对应当时的配置及网络，不代表任意 R2／S3 服务均已验收；后续保存状态问题由本版修复。
- 真实 R2 大型加密备份上传、下载恢复、宝塔实机部署、Docker 大于 64 MiB 的加密恢复完整链路和连续 24 小时稳定性仍需单独验收。只读桶鉴权或测试对象通过不能代替完整恢复验证。
- 发布不会自动替换现有本机程序；安装与配置变更以部署操作为准。
