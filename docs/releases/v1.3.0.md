# Release v1.3.0 - 用户端与管理端分离及独立账户管理

本地候选版本，尚未发布 GitHub Release。

## 新功能

- 用户端拥有独立页头和导航：监控、作品公开浏览；普通用户注册、登录后使用自己的 API Key 进行文本/动画在线测试，并在个人账号页修改密码或退出登录。
- 管理端使用独立登录页、管理导航、工作台和“访问用户端”入口。系统设置、在线升级、平台、模型、任务和用户管理只在管理端显示。
- 后台用户管理分为普通用户与管理员两个列表，支持新增、启用、停用和重置密码。当前管理员不能停用自己，不能通过管理接口重置自己的密码；最后一个可用管理员受事务保护。
- 普通用户与管理员使用独立账户表、会话 Cookie 与 CSRF Token；用户注册不能创建管理员。在线测试在服务端强制验证普通用户会话，管理员会话不能替代。

## 迁移与安全

- 数据库自动迁移到 schema 2，保留既有管理员及会话、平台配置、加密密钥、任务和作品。先备份再升级；普通用户账号初始为空。
- 原 schema 1 备份可在临时恢复目录校验后迁移到 schema 2。未来版本、不完整数据结构、错误密钥和损坏归档继续拒绝恢复；不修改原备份 ZIP。
- 旧 schema 1 程序不能直接回退运行已迁移的 schema 2 数据。如需降级，必须同时恢复完整的迁移前数据备份。
- 本版包含本地 1.2.3 的进程占用保护与升级修复，协议仍为 2，要求 `usage_guard: 1`。v1.2.2 及更早版本须先一次性部署完整程序和启动器包。

## 入口

- 用户端：`/`；注册 `/register`；登录 `/login`；账号 `/account`；在线测试 `/test`。
- 后台登录：`/admin/login`；首次初始化 `/admin/setup`；后台工作台 `/admin`；用户管理 `/admin/users`。
- 用户端不展示管理菜单。退出、会话过期和密码修改后回到各自独立的登录入口。

## 验证

- Go 数据迁移、账号生命周期、禁用/密码重置后的会话撤销、两类 Cookie/CSRF 隔离、匿名与管理员直接调用测试接口拒绝等回归。
- Chrome 浏览器覆盖独立布局、安全登录回跳、移动端、注册后测试入口、用户停用/启用/重置、原管理员操作及公开页。
- 全部测试使用隔离账户和目录，实际平台 API Key 不进入测试产物或源码。

## 已知限制

- 普通用户注册使用用户名和密码，不提供邮件验证或找回密码；忘记密码由管理员重置。
- 本地候选版尚未执行发布流水线；Linux arm64 真实运行未执行。
