# Release v1.2.3 - 修复升级恢复与进程占用保护

当前为本地验证候选；本轮未创建或推送 v1.2.3 Tag，未发布 GitHub Release。v1.2.2 发布说明继续保留作为历史记录。

## 修复

- 检查更新后保存的 Release 在进程重启后重新建立下载和校验元数据，避免下载地址丢失。
- 自动下载完成后保持真实结果，修复错误地报告失败及重复下载同一安装包的问题。
- 升级历史直接跟随状态轮询快照，检查或下载在后台完成后更新历史记录。
- Worker 在旧租约尚未失效时采用有界等待，防止重启后过早判定无法启动。
- 服务端与 Worker 在数据库整个打开期间持有占用锁；启动器同时登记其启动的进程，覆盖首次状态报告之前、数据库关闭之后进程仍存活的时段。替换或恢复前核对占用与存活进程，阻止遗漏旧进程后继续安装。

## 安装与迁移

- Windows amd64 完整包名为 `relaylab-windows-amd64-1.2.3.zip`；Linux amd64 / arm64 完整包名为 `relaylab-linux-架构-1.2.3.tar.gz`。完整包包含服务端和启动器两份程序、脚本与部署示例。
- **v1.2.2 及更早版本升级到本版时，先手动部署一次完整安装包，同时替换服务端、启动器及脚本。** 先停止旧程序并确认网站和 Worker 已退出，备份数据库与 master.key；保留原 data 和 config.yaml，再启动本版。只替换 relaylab.exe 不会更新启动器占用保护。
- 启动器协议保持 2，数据库 schema 保持 1；Manifest 新增必填 `usage_guard: 1`。旧版严格 Manifest 解析器会拒绝新字段，避免新应用搭配旧启动器。完整迁移后再使用在线升级。
- 默认本机地址仍为 `http://127.0.0.1:42783`。启动后核对当前版本 1.2.3、Worker 在线及原平台、任务、历史数据。

## 本地验证

- 前端回归覆盖检查、下载请求先受理、随后状态轮询返回完成结果和新历史的异步顺序。
- 打包测试覆盖三平台完整包内的两份程序、Manifest 的 `usage_guard: 1`、资源校验及缺少占用保护字段时拒绝包契约。
- 已在本机通过：`npm test -- --run src/pages/Updates.test.tsx`（11 项）、`npm run typecheck`、`python -m unittest discover -s scripts -p test_release.py -v`（9 项）。这些结果不表示发布 CI 或公开发布已经完成。

## 已知限制

- 本版仍需一次完整安装迁移，应用在线更新不能替换当前启动器自身。
- Linux arm64 的真实启动和升级验证仍需在 arm64 主机执行。
- GitHub 附件使用 HTTPS 与 SHA-256 校验，当前没有独立签名信任链。
