# Release v1.4.2 - 修复 HTML 依赖漏洞与 Docker 数据恢复

## 发布信息

- 类型：正式稳定补丁版，Tag `v1.4.2`，版本来源为根目录 `VERSION`。
- 支持 Windows amd64、Linux amd64、Linux arm64。
- Schema 3、launcher 协议 2、`usage_guard: 1` 保持不变。

## 安全修复

- 将 `golang.org/x/net` 从 v0.61.0 升级到 v0.62.0，修复作品 HTML 解析/渲染调用路径涉及的 **GO-2026-6860** 和 **GO-2026-6866**。
- 继续使用不授予同源权限的 iframe 沙箱及 CSP；升级依赖不放宽生成脚本、外部资源、主页面和 Cookie 的隔离边界。
- 发布 CI 增加固定版本 `govulncheck` 的可达漏洞检查，以及 npm 高危及以上漏洞检查。

## 修复与验证补充

- 修正 Docker 恢复说明：`restore` 必须使用空数据目录，不能停止旧容器后直接覆盖原卷。现在通过 `RELAYLAB_DATA_VOLUME` 选择新卷，恢复验证成功后再切换，原卷保留。
- 源码及 Linux 完整包的 Compose 均支持显式数据卷名称；默认卷名维持 `relaylab_relaylab-data`，既有默认部署不会切换到空卷。
- 补充私有历史跨用户访问、混合所有者批删原子性、管理员/用户权限隔离、单模型定时任务最终派发、双模板及失效目标回归。
- 更新预览浏览器测试的页面定位方式，保留主页面、Cookie、源码下载和手机布局的验证断言。

## 安装与升级

1. v1.4.1 及 v1.4.0 原生安装可使用后台检查、下载并安装本版；建议先备份数据库及 `master.key`。
2. 新安装选择对应架构的完整包；Windows 为 `relaylab-windows-amd64-1.4.2.zip`，Linux 为对应 `amd64` 或 `arm64` 的 `.tar.gz`。
3. 容器部署使用新版本源码或完整包重建镜像，再重建容器，保留既有数据卷；不要仅修改版本号后继续运行旧镜像。容器内应用自更新仍关闭。
4. Docker 数据恢复按[本版部署说明](https://github.com/70548887/relay-api-monitor/blob/v1.4.2/docs/DOCKER.md)执行：选择全新卷名、恢复、检查，再启动；不要删除原卷。
5. v1.2.2 及更早原生安装须按[升级说明](https://github.com/70548887/relay-api-monitor/blob/v1.4.2/docs/UPDATES.md)先更新完整启动器及脚本。

本版不会重置管理员或用户账号、API Key、公开设置、历史作品及私有测试记录；不自动改变单模型选择或调用参数。

## 附件与校验

固定 11 个附件：三个系统/架构各一份主程序及启动器（6 个裸程序）、3 个完整部署包、`manifest.json`、`SHA256SUMS`。

Manifest 记录版本、完整 Commit、统一 UTC 构建时间、兼容范围和每个附件大小/SHA-256。发布流程先上传草稿，重新下载全部附件并校验后，才发布为正式版和 latest。v1.4.1 的历史 Tag 和附件不会覆盖。

```sh
sha256sum -c SHA256SUMS
```

Windows 可对照 `SHA256SUMS` 检查：

```powershell
Get-FileHash .\relaylab-windows-amd64-1.4.2.zip -Algorithm SHA256
```

## 验证与已知限制

- Go 全量及权限/调度回归、150 项前端单元测试、浏览器预览/页面检查、Windows 实际二进制升级恢复，以及打包校验已在本地执行；HTML 依赖升级后，可达 Go 漏洞扫描为 0，npm 审计为 0。
- 正式发布还须通过 Windows/Linux 升级恢复、Linux 并发检查、Docker amd64 与 arm64/QEMU 的源码/完整包镜像验证，以及 Compose 新卷恢复流程检查。以本版 GitHub Actions 成功结果为准。
- 本机没有 Docker Engine；容器运行验证由 CI 执行，QEMU 结果不等于所有宝塔 ARM 实机环境都已验证。
- 连续 24 小时稳定性验收尚未完成。测试使用隔离数据和本地协议夹具，没有新增真实模型调用；不将夹具结果当作所有上游平台的可用性证明。
- `govulncheck` 会额外列出未使用的 `openpgp` 模块级公告，本项目没有导入该包或调用相关函数；这与调用路径中漏洞数为 0 并不矛盾。
