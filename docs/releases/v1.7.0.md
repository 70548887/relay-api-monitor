# Release v1.7.0 - 模型指纹匹对

## 发布信息

- 类型：正式功能版本；Tag `v1.7.0`，版本来源为根目录 `VERSION`。正式发布状态与时间以 GitHub Release 为准。
- 支持 Windows amd64、Linux amd64 和 Linux arm64。数据库升级为 Schema 5，首次启动可把 Schema 1／2／3／4 自动迁移为 5；launcher 协议 2、`usage_guard: 1` 与 `restore_v1` 能力要求不变。
- Schema 5 迁移不可回退：已迁移的数据库不可再交给仅支持 Schema 4 或更早版本的旧程序。升级前保留数据库与 `master.key` 的备份；需要回到旧版本时只能恢复该备份，并会丢弃备份之后的数据。

## 模型指纹匹对

- **平台检测**：管理员在后台“指纹匹对”为每个模型选择对照的参考模型（默认按上游模型 ID 自动匹配）、每轮题数（1–3 题）和是否定时；定时默认关闭，打开后按设定间隔（默认每 24 小时）检测一轮，也可随时手动检测。平台检测的每轮结果保存在站内，公开模型的结论显示在 `/fingerprint`。
- **结论分量**：一轮最多 3 道题，每题要求模型写出约 300 个整数。3 个有效回答给出完整结论与置信度，2 个仅供参考，1 个仅作测试；结论分为一致、同家族不同型号、不一致、未收录和无法判定。
- **公开结论**：`/fingerprint` 为每个公开模型取最近 3 轮中多数轮次得出的结论，并展示得出结论的那一轮明细与该模型最近 30 轮检测历史。置信度是参考库范围内的概率，不是身份证明。
- **手动粘贴**：无需登录，公开页面和 API 均可使用；本系统不向任何模型接口发送请求，粘贴的回答只在当次比对中使用、不保存。默认每个 IP 每分钟最多比对 10 次，可在后台调整。
- **通过 API**：需要普通用户登录，使用用户自己保存的连接发题；结果只返回给本人一次，不保存、不公开。默认每个用户每小时最多检测 6 轮，可在后台调整。
- **参考库**：默认在线获取 lm-detector 的参考库；也可在“系统设置 → 指纹匹对”填写服务器上的本地绝对目录，该目录须包含 `unified_bank.json` 和 `shared_detector.bin`。参考库不可用时不能检测，也不会向上游发送题目请求。
- **用量与并发**：除手动粘贴外，每轮检测都会向上游发送真实请求并产生用量；每题提示词约 1 KB，要求输出 292–332 个整数。平台检测沿用该模型的作品输出上限，自助检测的输出上限为 8,192（Anthropic Messages 协议为 32,000）。默认检测并发为 1，可在后台调整。
- **来源与许可**：参考库与 Go SDK 来自 [lm-detector](https://github.com/Ikaleio/lm-detector) 项目（MIT 许可），第三方声明已列出相应许可。

## 安装与升级

1. 升级前保存数据库与 `master.key` 的受限安全快照，并保管离线恢复私钥；保留既有配置和持久数据目录。详见[备份说明](https://github.com/70548887/relay-api-monitor/blob/v1.7.0/docs/BACKUPS.md)。
2. 确认相关实例一并升级，不要只回退程序二进制；Schema 5 数据库无法被仅支持 Schema 4 或更早版本的程序打开，需要回退时按升级前的备份恢复。
3. 原生部署从 v1.6.3 升级时，可用后台在线升级或同架构的完整安装包；v1.2.2 及更早版本需先部署一次包含服务端与启动器的完整安装包。详见[升级说明](https://github.com/70548887/relay-api-monitor/blob/v1.7.0/docs/UPDATES.md)。
4. Docker／宝塔容器部署须重建目标版本镜像和容器，并保留原持久卷；升级后核对网站与 Worker 的实际版本及健康状态。部署参考见[Docker 与宝塔部署](https://github.com/70548887/relay-api-monitor/blob/v1.7.0/docs/DOCKER.md)。

## 附件与校验

稳定 Release 固定 **11 个附件**：Windows amd64、Linux amd64、Linux arm64 各有服务端和 launcher 裸可执行文件，共 6 个；Windows 完整 ZIP 和两个 Linux 完整 tar.gz，共 3 个；另有 `manifest.json` 和 `SHA256SUMS`。

- Windows：`relaylab-windows-amd64-1.7.0.zip`
- Linux x86_64：`relaylab-linux-amd64-1.7.0.tar.gz`
- Linux ARM64：`relaylab-linux-arm64-1.7.0.tar.gz`

Manifest 须包含与 Tag 一致的版本、完整源码 Commit、统一 UTC 构建时间、`database_schema: 5`、`min_database_schema: 1`、`launcher_protocol: 2`、`usage_guard: 1`，以及 9 个程序／压缩包的名称、系统、架构、大小与 SHA-256。`SHA256SUMS` 覆盖这 9 个程序／压缩包和 Manifest，路径只使用文件名；下载后可在同一目录执行 `sha256sum -c SHA256SUMS`。流水线先上传草稿、下载并逐项校验文件名、大小和 SHA-256，通过后再发布正式版。完整包不包含数据库、`master.key`、真实本机配置、Token 或日志。

## 验证与已知限制

- 发布门禁包括 Go 全量测试与 `go vet`、前端测试、类型检查和构建、打包回归、Linux race 检查、Windows／Linux amd64 的真实二进制备份恢复和升级回退、Docker amd64／arm64 构建运行及依赖安全审计。门禁要求不等于本版已通过；结果以 v1.7.0 的实际 CI 和 Release 记录为准。
- npm 生产依赖审计须无漏洞。完整审计仅对锁文件中 picomatch 4.0.7 的 GHSA-fc5q-39xc-vjpf（source `1247710`）及六个准确的开发／构建／测试依赖条目保留限时例外，绑定最终锁文件 SHA-256，截止 `2026-11-25T00:00:00Z`；本版把前端包版本号更新为 1.7.0 会改变锁文件根版本，例外绑定的哈希随发布提交更新，具体哈希以发布提交为准。其他发现或审计异常必须阻止发布。相关风险和门禁见[发布规范](https://github.com/70548887/relay-api-monitor/blob/v1.7.0/docs/RELEASE.md)。
- 指纹检测依赖参考库与上游可达：参考库不可用或无法下载、读取时不能检测；上游不可达或请求失败时对应题目会失败，平台检测在没有收到任何回答时整轮记为失败，其余情况按已到达的回答评分并在结果中列出失败题目，没有有效回答时结论为无法判定。
- 公开结论是最近 3 轮多数决的统计比对结果，不等于逐字证明，也不构成对上游身份或模型来源的证明。
- ARM64 容器检查如通过 QEMU 执行，不等于原生 ARM64 主机验收。真实线上实例、宝塔服务器实机、大型加密备份恢复与连续 24 小时稳定性需单独验证；此说明不代表已在用户服务器部署或验证。
