# 1.1.1 — Anthropic 流终态诊断

- Anthropic 流缺少 `message_stop` 或 `stop_reason` 时使用专门错误码 `anthropic_missing_terminal`，页面提示将 Thinking 恢复为“上游默认”后重试。
- 不完整流不会发布 HTML/SVG 作品，也不会把 artifact 事件误报为完整成功。

# 1.1.1 — 稳定性与诊断

- Anthropic 缺少 `message_stop/stop_reason` 时返回专用错误码和恢复提示，避免把 artifact 误报为完整成功。
- Windows 数据目录不再强制重写 ACL，避免受限进程无法访问数据库和构建测试；渠道 Key 仍使用 AES-GCM 加密保存。
- 完整回归重新通过：Go 全包测试、vet、前端37项测试、TypeScript检查和npm审计。

# 1.0.1 — 审计修复

- 新增模型默认关闭自动检测和作品任务，归档、停用或缺失对象不再作为手动运行目标；编辑平台和分组保留未展示字段。
- 退出和会话失效时清除管理缓存，拒绝旧请求恢复过期会话；访客请求取消和后续请求状态独立，筛选变化清除无效作品比较。
- SQLite immediate 写事务解决独立连接读后写争用；配置、计划和取消在事务中一致更新。
- 全局 Worker 租约接管后取消旧请求，旧任务不能继续续租或提交；同步结果按配置版本检查，过期响应不覆盖新配置。
- 修复调短周期仍等待旧时间、发现配置更改沿用旧等待时间，以及一万条记录截断导致的统计和批量取消遗漏。
- 登录使用统一口令验证路径，昂贵密码计算全局并发限制为2；加强初始化 Host、Origin、JSON完整性与请求体大小校验。
- 上游地址先进行 IDNA 规范化再验证保护规则；修复 Responses 终态和 CR 分隔SSE阻塞；限制每次SSE写入等待。
- 公开数据使用明确字段与参数白名单；HTML提取依据真实标签边界，避免注释伪标签或两份文档被错误合并。
- 主密钥以完整文件原子发布，支持并发初始化；备份文件限制访问权限，恢复验证成员长度、CRC和版本，不发布损坏备份。
- 优雅停止等待请求处理完成后关闭数据库；拒绝未知命令的文件副作用，并限制新数据目录只能使用专用位置。
- 发布使用全新暂存目录，源码发布采用指定目录与文件列表，避免打包旧运行数据、环境文件和自定义私密目录。
- 更新接口文档的写入模型、创建状态码、历史条数和413错误说明。
