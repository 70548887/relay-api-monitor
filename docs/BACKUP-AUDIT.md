审计日期：2026-10-30。依据用户提供的《Relay Lab 数据备份与恢复开发设计方案》，审查当前工作区源码、接口、页面、脚本和发布契约，并为确认问题补充复现与回归。

本次确认的问题已修复。此结论只覆盖已检查实现和已执行测试，不把本地夹具视为真实存储提供商或生产部署验收。

后续第二轮审计另发现六项边界问题及云端目录导入遗漏，已在修复轮次处理，详见 [第二轮修复记录](BACKUP-REPAIR.md)。原始第二轮结果保留在隔离审计目录中，不作为当前未修复状态。

## 影响数据安全的修复

1. **跨实例误恢复（P1）**：兄弟数据目录原先共用恢复指针。改为按规范化数据目录建立独立目录，并校验预检、操作及指针归属。无归属旧候选日志拒绝自动执行。
2. **恢复日志不够持久（P1）**：除文件内容同步外，Unix 同步父目录、Windows 使用 WRITE_THROUGH。最终备份包发布同样保持不覆盖和持久性。
3. **永久归档保护的崩溃窗口（P1）**：归档槽位和完成记录在同一 SQLite 事务提交；读取/删除联查槽位，明确解除保护也保留历史日期。复核可以从发布前的可信索引恢复原归档策略。
4. **前置失败留下服务停止（P1）**：排空、部分停止或安全快照失败时，使用独立上下文恢复原服务；无法恢复则保持需要恢复状态。公共启动/继续接口不能绕过恢复事务。
5. **网络错误覆盖恢复日志（P1）**：回执丢失只记录独立的显示信息，不再覆盖 launcher 已推进的替换阶段。明确拒绝使用失败终态，同一预检不能重复提交。
6. **崩溃后重新制造可信摘要（P2）**：密文摘要在最终文件发布前持久保存；中断恢复必须与原摘要匹配。缺摘要或篡改文件标记待重新校验，不自动判成功。
7. **S3 重试覆盖同名对象（P2）**：先回读核对已存在对象；新写入采用条件创建，已存在不同内容拒绝覆盖。上传回执丢失后可通过回读完成，不重复 PUT。
8. **新卷旧索引与保护信息（P2）**：复核数据库与外部目录的并集；缺失/不可验证副本保持冻结。纯本地副本遗失需明确确认，云端失败不能绕过校验。

## 运行与界面闭环修复

- 查询未完成任务不再截断于最近 1000 条；最近成功与当前操作独立查询，不被最近 100 条失败遮蔽。
- 启动时锁繁忙会重试恢复；每小时使用同一候选计算执行保留清理，并安全清理超过 2 小时的模块临时物。
- 真实阶段记录校验/加密；错误、时长、已传输字节和独立本地/远端副本状态可查询。
- 管理页面支持数据库层的状态、来源、保护及日期筛选；修改保留规则前预览受影响副本，并确认后保存。
- 健康状态按存储修订独立记录，测试未保存的新配置不会冒充当前配置健康。
- 管理员再次验证输错密码不清除有效会话。
- 恢复使用独立只读进度页，旧会话失效仍能等待结果；状态凭证只在标签页内存中，不进入 URL 或持久存储。
- 上传上限统一为 3 GiB；新增独立 `verify-backup` 命令，只检查暂存副本，不打开当前配置/数据库。
- 不支持在线恢复时，原生与 Docker 分别提供正确离线步骤，原生页面不会误引导创建 Docker 数据卷。
- 管理端重型校验/传输请求最多同时 2 个，备份任务并发 1；新下载遵守维护状态并计入排空。单条传输流约 32 MiB/s，支持超时和取消。
- 数据库除物理完整性外也检查外键关联，关联损坏的快照不会被发布或恢复。

## 对照方案的覆盖结论

- **归档/密钥**：一致性 SQLite、新旧格式、整包 age 加密、公私钥匹配及实际加解密、成员摘要、Schema 分离、受限暂存和全部凭据校验均实现。
- **任务/调度**：独立于模型 Worker、手动幂等、计划时间唯一、防积压、停机不补跑、进程中断核对及真实状态持久化均实现。
- **S3/保留**：读写删连接测试、文件流、回读摘要、修订引用、错误副本保留、普通保留/月度归档/永久保护及删除重试均实现。
- **原生恢复**：预检、最多 660 秒排空、进程使用锁、安全快照、匹配 DB/key 安装、失败恢复、清会话、防旧队列重放及恢复后索引冻结均实现。
- **Docker**：新空卷恢复脚本、原卷保留、只读输入、无 Docker socket 和拒绝误用卷均实现；实机容器验收仍未执行。
- **界面/契约**：管理员专属三标签、健康/预计时间、筛选、清理预览、详情、下载及真正执行恢复后的独立进度页均闭环；OpenAPI 与前端类型已更新。
- **打包/文档**：Schema 4、launcher 协议 2/restore_v1、旧版本兼容判断、Windows/Linux 构建及秘密排除规则已接入。
